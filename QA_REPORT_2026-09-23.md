# Article Saver 1.2.0 — pre-publication QA

Reviewed on 23 September 2026 against `main` at `577dff5`, followed by the fixes documented below.

## Decision

The release candidate is ready for the remaining manual Store gates after rebuilding from the fixed source. Automated correctness checks, browser regression checks, deterministic packaging, Product Design review, and a standard Codex Security scan were completed. No critical or high-severity issue remains in the fixed source.

## Functional QA

- First-party JavaScript syntax: passed.
- Node regression suite: 50/50 passed.
- Browser regression suite: 19/19 passed.
- Import/export round trips preserve AI summaries, AI chat, notes, tags, highlights, list identity, and the selected destination list.
- Excel output preserves formatted chat, summary and note highlights, sortable numeric dates, safe text cells, list-scoped exports, and valid unique sheet names.
- Store ZIP is produced from an explicit runtime allowlist and excludes tests, screenshots, development scripts, and Git metadata.

## Product Design audit

1. **Share setup — healthy.** The content controls, message preview, privacy note, and primary action have a clear hierarchy. Checkbox labels are exposed to accessibility APIs.
2. **Import destination — healthy.** The user can select an existing list or create a new one. Metrics and the local-only notice clarify the result before committing.
3. **Share completion — healthy.** The saved filename and the next two actions are concise and easy to scan.
4. **Success notification — healthy.** The toast is compact, dismissible, and exposed as a status message.
5. **Installed side panel — healthy after adjustment.** The core save action remains visible at narrow side-panel width. Article titles and source metadata now use automatic text direction so English titles align naturally inside a Hebrew interface.

The audit used fresh screenshots of all four transfer fixtures and the installed Chrome side panel. Screenshot review alone does not establish keyboard focus order, screen-reader announcements, or WCAG contrast ratios; those remain manual accessibility checks.

## Codex Security

The immutable pre-fix scan found one low-severity, high-confidence unsafe-rendering path in the share-preview badge: an imported list name or article title could create extension UI markup. The name is now escaped before insertion into `innerHTML`.

Broad HTTP/HTTPS host access remains intentionally enabled because full-window mode must extract from the most recently used article tab. This permission must be described accurately in the Chrome Web Store privacy and permission declarations.

The bundled XLSX library is reached through export generation only; no workbook-import parser entry point was found. Imported `.articlesaver` packages are bounded to 50 MiB and 500 articles, validate schema and identity, normalize known fields, and write transactionally.

## Remaining manual Store gates

1. Reload the unpacked extension after the final commit and check the service-worker error panel.
2. Use a non-sensitive article and the publisher's Gemini key to verify model refresh, summary, and chat, then inspect quota or billing.
3. Open the generated workbook in desktop Excel and inspect every sheet, dates, chat formatting, highlights, and hyperlinks.
4. Use the public repository privacy policy URL in the Store dashboard and complete the data-use and broad host-permission declarations.
5. Confirm the Store listing screenshots match version 1.2.0 and upload the final ZIP only after its checksum matches the release artifact.
